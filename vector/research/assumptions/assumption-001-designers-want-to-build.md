# Assumption 001: Designers Want to Build Directly

**Status:** hypothesis
**Risk:** High (Impact: High × Confidence: Medium)
**Personas:** persona-001, persona-003

## Statement

A meaningful segment of mid-career designers want to build directly in code (with AI assistance) rather than producing static deliverables for handoff — and they want to do this while remaining designers, not becoming engineers.

## Why This Matters

If this is wrong, Zero Vector's core value proposition collapses. The manifesto, the curriculum, and the Investiture framework all assume designers will adopt code-adjacent workflows. If most designers prefer to stay in Figma and let the handoff problem be solved by better tooling (e.g., Figma-to-code), then Zero Vector is solving the wrong problem.

## Signals That Support It

- Steady growth of "design engineer" role in job postings (2024–2026)
- Designers adopting Cursor, v0, and AI coding tools independently
- Community engagement with the manifesto content (if measurable)
- Frustration with handoff degradation is well-documented in design discourse

## Signals That Would Invalidate It

- Designers try the curriculum and drop off at the code-literacy modules
- Survey data showing designers prefer improved handoff tools over building directly
- Market converges on Figma-to-code pipelines that preserve intent without designer involvement in code
